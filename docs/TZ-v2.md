## 1. Продукт

Поисковый и аналитический слой над рынком недвижимости Греции.

Один запрос → много источников → один объект вместо дублей → история цены → сравнение цен между источниками → прямая ссылка на оригинал.

Уровень продукта в перспективе сопоставим с CASAFARI по модели данных, но первый пользователь — частный покупатель.

---

## 2. Правовая модель (по образцу CASAFARI)

Продукт позиционируется как **поисковая система по объявлениям**, а не как портал.

1. Мы **не публикуем** объявления, а индексируем их. Автор объявления — источник.
2. В каждой карточке виден источник: «Source: ABC Real Estate». Каждое объявление имеет прямую ссылку на оригинал.
3. Обрабатывается только **публично доступный** контент. Не обходим логин, CAPTCHA, Cloudflare challenge, платный доступ.
4. **robots.txt — по правилу Spiti Radar** (решение владельца продукта, 27.09.2026). Общий запрет для всех ботов (`User-agent: *` + `Disallow: /`) не считается запретом для нас: многие сайты агентств стоят на шаблоне «Google можно, остальным нельзя». Соблюдаем:
   - явный запрет для нашего бота (`User-agent: SpitiRadar`) — сайт исключается;
   - `Crawl-delay` и не менее 3 секунд между запросами к одному сайту, не больше одного обхода сайта в сутки;
   - честный User-Agent с названием и ссылкой на страницу opt-out;
   - собираем только страницы объектов, без личных кабинетов, форм и поиска с параметрами;
   - opt-out по запросу владельца (раздел 13) — в течение 72 часов.
   Риск: владелец сайта или портала может счесть сбор нарушением своих условий; при претензии источник исключается немедленно.
5. Фото: показываем **миниатюры** и ссылку на галерею источника. Полноразмерные фото не храним.
6. Текст: чужое описание не копируем. Показываем **своё описание**, сгенерированное из нормализованных характеристик.
7. Персональные данные: основание — законный интерес (GDPR, legitimate interest). Контакты не продаём и не экспортируем. Телефоны и имена частных лиц не храним.
8. В пользовательском соглашении: данные предоставляются «как есть», цены и расчёты — справочные, решение о покупке принимает пользователь.

## 4. Специфика греческого рынка

Этот раздел — ключевой для качества аналитики. Без него средние цены, отклонения от рынка и «выгодные предложения» будут ложными.

### 4.1 Сегмент рынка (`market_segment`)

Каждый Listing и каждый Property обязательно получает сегмент. Аналитика считается **только внутри сегмента**.

| Сегмент | Код | Попадает в рыночные аналоги |
|---|---|---|
| Обычная вторичка | `resale` | да |
| Новостройка / строящийся объект | `new_build` | только в аналоги новостроек |
| Аукцион | `auction` | нет |
| Банковские / сервисерские объекты | `servicer_reo` | нет (отдельная аналитика) |
| Доля в собственности (εξ αδιαιρέτου) | `partial_share` | нет |
| Голая собственность (ψιλή κυριότητα) | `bare_ownership` | нет |
| Земля / участок | `land` | только в аналоги земли |
| Коммерческая недвижимость | `commercial` | только в аналоги коммерции |
| Не определён | `unknown` | нет, до ручной проверки |

Каждый сегмент имеет `segment_confidence`. При низкой уверенности объект не участвует в расчёте медиан.

### 4.2 Аукционы (πλειστηριασμοί)

Проблема: квартира 50 м² выставлена за €20 000 — это стартовая цена торгов, а не рыночная. Если такой объект попадёт в выборку, весь анализ «выше/ниже рынка» сломается.

Правила:

1. Аукционные объекты определяются по:
   - источнику (площадки электронных торгов, например eauction.gr; сайты сервисеров);
   - ключевым словам в тексте: `πλειστηριασμός`, `πλειστηριασμού`, `τιμή πρώτης προσφοράς`, `auction`, `e-auction`, `ηλεκτρονικός πλειστηριασμός`;
   - наличию даты торгов;
   - статистическому признаку: €/м² ниже 40% медианы сегмента `resale` в районе → флаг `suspected_auction_or_special` и ручная проверка.
2. Аукционы **исключаются** из медиан, аналогов и Match Score по цене.
3. Для аукционов показывается отдельная карточка: стартовая цена, дата торгов, статус (при наличии), предупреждение:
   «Цена аукциона — стартовая, а не рыночная. Объект может быть занят, иметь обременения, осмотр может быть невозможен.»
4. Аукционы — отдельный фильтр и отдельный тип уведомления. По умолчанию в обычном поиске они **скрыты**, пользователь включает их явно.
5. Если тот же физический объект позже появляется в обычной продаже (после покупки на аукционе) — это новый `market_episode` того же Property (раздел 5.4). История аукциона сохраняется и показывается.

#### 4.2.1 Выдача аукционов

Аукционы — отдельный продукт внутри платформы, а не просто исключение из аналитики.

1. **Отдельный поиск аукционов**: район, тип, площадь, стартовая цена, дата торгов, площадка, статус (предстоит / перенесён / состоялся / отменён).
2. **Блок «Аукционы в этом районе»** в обычной выдаче: под основными результатами отдельной строкой — «В Kalamaria сейчас 7 объектов на аукционе, стартовые цены €18k–€95k → показать». В общий список и сортировку они не смешиваются.
3. **Блок «Рядом на аукционе»** на карточке обычного объекта: аукционные объекты того же сегмента в радиусе 1 км, со стартовой ценой и датой торгов.
4. Для аукционного объекта — сравнение стартовой цены с медианой обычной вторички района (с пометкой, что это сравнение справочное).
5. Уведомления: новый аукцион в районе сохранённого поиска, перенос даты торгов, повторные торги со сниженной стартовой ценой.
6. Источники аукционов и сервисеров — `data/sources/auctions_servicers.csv`.

### 4.3 Банковские и сервисерские объекты

Объекты банков и сервисеров (компании, управляющие проблемными кредитами) часто выставляются по заниженной цене, с обременениями, в плохом состоянии.

- Отдельный сегмент `servicer_reo`.
- Определение: по агентству/источнику (реестр сервисеров в Source Registry, поле `source_kind=servicer`), по ключевым словам.
- В медианы обычной вторички не попадают.
- Для инвесторов — отдельная аналитика этого сегмента.

### 4.4 Застройщики и новостройки

Проблемы:

- цена ставится «от балды» или как ориентир «от €X»;
- цена может быть с НДС или без (строительные объекты);
- один проект = десятки почти одинаковых квартир;
- объект может быть ещё не построен (off-plan, υπό κατασκευή), без года постройки.

Правила:

1. Отдельный сегмент `new_build` и отдельная сущность **Project** (жилой комплекс): застройщик, адрес, срок сдачи, количество квартир.
2. Property новостройки привязывается к Project. Внутри проекта квартиры различаются этажом, площадью, номером/буквой квартиры, ориентацией.
3. **Дедупликация внутри проекта ужесточается**: совпадение района, площади и цены недостаточно. Требуется совпадение этажа + площади ±2% + (номер квартиры или фото). Иначе — разные Property. Это защита от ошибочного объединения соседних квартир.
4. Цена с пометкой «от» (`price_type=from`) не участвует в медианах.
5. Новостройки сравниваются только с новостройками. Медиана новостроек и медиана вторички показываются раздельно.
6. Поле `vat_included`: true / false / unknown.

### 4.5 Одно объявление в нескольких районах (подмена геолокации)

Проблема: агенты публикуют одну и ту же квартиру в нескольких районах или ставят адрес соседней улицы, которая формально в другом районе, чтобы охватить больше поисков. Система видит «разные квартиры в разных районах».

Правила:

1. **Район не является обязательным условием совпадения** при дедупликации. Кандидаты ищутся в радиусе (по умолчанию 3 км для Салоник) и по соседним районам.
2. Главный сигнал для таких случаев — **фото**:
   - при обработке для каждого фото считается перцептивный хэш (pHash/dHash), само фото не хранится;
   - совпадение ≥ 3 фото (расстояние Хэмминга ≤ порога) между двумя Listing → сильный сигнал одного объекта независимо от района.
3. Дополнительные сигналы: площадь, этаж, комнаты, год, агентство, телефон агентства, хэш текста описания (minhash), цена.
4. Если Listings одного Property указывают разные районы — у Property ставится `geo_conflict=true`:
   - район Property выбирается по приоритету: точные координаты > адрес с номером дома > район портала с максимальным доверием > большинство источников;
   - `geo_confidence` снижается;
   - объект попадает в очередь **Location Review** в админке.
5. Один агент/агентство, публикующий одинаковые фото в разных районах, получает счётчик `geo_spam_score`. Источники с высоким счётчиком получают пониженное доверие к геоданным.
6. В поиске по району объект с `geo_conflict` показывается один раз, с пометкой «район указан источниками по-разному».

### 4.6 Границы районов

- Названия районов у порталов и агентств не совпадают с официальными границами. Пример: «Kalamaria», «Martiou», «Analipsi» используются как соседние районы, но административно относятся к разным муниципалитетам (Καλαμαριά и Δήμος Θεσσαλονίκης).
- Location Dictionary хранит **две иерархии**:
  - административную (Περιφέρεια → Περιφερειακή Ενότητα → Δήμος → Δημοτική Κοινότητα);
  - «рыночную» (районы, как их называют покупатели и порталы).
- Каждый рыночный район имеет полигон (рисуется вручную, на базе OpenStreetMap) и список соседних районов.
- Поиск по району по умолчанию ищет строго в полигоне; опция «+ соседние районы».

### 4.7 Площадь

- В Греции указывают **μικτά** (общая, с долей общих помещений) и **καθαρά** (чистая) площадь. Разница обычно 10–25%.
- Хранить `area_gross`, `area_net`, `area_type_unknown`.
- €/м² считается по одному типу площади внутри выборки (по умолчанию gross, т.к. он встречается чаще). Если тип неизвестен — флаг, объект участвует в медиане с пониженным весом.
- Дедупликация: допуск по площади учитывает, что один источник мог дать gross, другой — net.

### 4.8 Этажи

Нормализованный этаж (`floor_normalized`) и исходное значение (`floor_raw`):

| Греческий термин | Значение | Код |
|---|---|---|
| υπόγειο | подвал | -1 |
| ημιυπόγειο | цокольный (полуподвал) | -0.5 |
| ισόγειο | первый (нулевой) этаж | 0 |
| υπερυψωμένο | приподнятый первый этаж | 0.5 |
| 1ος, 2ος… | этаж N | N |
| ρετιρέ | пентхаус / последний отступной | N + флаг `penthouse` |
| μεζονέτα | двухуровневая | флаг `maisonette` |

Фильтр «не цоколь» исключает `-1`, `-0.5` и (по выбору) `0`.

### 4.9 Ошибки и ловушки в цене

Автоматические проверки для каждого Listing:

- цена < €1 000 или > €20 млн → ошибка ввода, в аналитику не идёт;
- цена похожа на €/м² (например, 1 800 при площади 70 м²) → флаг;
- цена похожа на аренду в объявлении о продаже → флаг;
- «Τιμή κατόπιν επικοινωνίας» / цена по запросу → `price=null`, `price_on_request=true`;
- резкое изменение цены > 30% за одно наблюдение → изменение подтверждается вторым наблюдением, до этого событие PRICE_CHANGE не создаётся и уведомление не отправляется;
- €/м² вне диапазона [P5; P95] сегмента района → флаг `price_outlier`, объект показывается, но не входит в медиану.

### 4.10 Юридический статус объекта (влияет на цену)

Отдельные признаки, извлекаемые из текста (с `confidence`):

- `bare_ownership` — ψιλή κυριότητα (продаётся без права пользования, цена сильно ниже);
- `partial_share` — продаётся доля (εξ αδιαιρέτου, ποσοστό);
- `occupied` — объект занят / сдан в аренду;
- `illegal_additions` — упоминание αυθαίρετα / τακτοποίηση;
- `inheritance` — наследство, документы не оформлены;
- `under_construction` — υπό κατασκευή.

Объекты с `bare_ownership` и `partial_share` исключаются из аналогов всегда.

### 4.11 Характеристики, специфичные для Греции

Извлекаются из структурированных полей и текста (EL):

- отопление: αυτόνομη / κεντρική θέρμανση, φυσικό αέριο, πετρέλαιο, αντλία θερμότητας, ηλιακός θερμοσίφωνας;
- διαμπερές (сквозная квартира), γωνιακό (угловая), προσόψεως (на фасад);
- πιλοτή (парковка под домом), αποθήκη (кладовая);
- энергокласс по ΠΕΑ (A+ … H);
- год постройки + год ремонта; признак «построено до 1985» (старые сейсмические нормы) — информационно;
- κοινόχρηστα (ежемесячные общие расходы).

### 4.12 Golden Visa

- Пороги Golden Visa зависят от региона и менялись (2024). Хранить таблицу порогов в конфигурации с датой актуальности, а не в коде.
- Фильтр «подходит под Golden Visa» — только как ориентир, с пометкой «проверьте условия у юриста».

### 4.13 Краткосрочная аренда

- Правила регистрации краткосрочной аренды в Греции ужесточаются по районам (особенно центр Афин). Инвестиционный режим показывает сценарий short-term только если для района нет известного запрета; таблица ограничений — в конфигурации с датой актуальности.

## 5. Сущности

### 5.1 Property

Физический объект. Имеет стабильный `property_id`, который сохраняется при объединении/разделении (старые ID переадресуются на новые).

Состояние Property: `ON_MARKET` (есть хотя бы один активный Listing) / `OFF_MARKET`.

### 5.2 Listing

Конкретное объявление у источника: `source_id`, `source_listing_id`, URL, нормализованные поля, `market_segment`.

**Состояние Listing** (что сейчас):

- `ACTIVE`
- `STALE` — не удалось проверить N раз подряд из-за ошибки источника;
- `REMOVED` — подтверждено: 404/410 или объявление пропало из выдачи источника K сканов подряд при успешном скане источника.

**События Listing** (что произошло) — в журнале `listing_events`:
`FIRST_SEEN`, `PRICE_DROP`, `PRICE_INCREASE`, `UPDATED`, `REMOVED`, `RELISTED`, `SOURCE_ADDED`.

REMOVED ≠ SOLD.

### 5.3 Observation

Каждая проверка Listing: время, цена, состояние, хэш ключевых полей, `scan_run_id`.

### 5.4 Market Episode

Период, когда Property был на рынке. Новый эпизод начинается, если Property был `OFF_MARKET` дольше 180 дней. Срок экспозиции и «первоначальная цена» считаются внутри эпизода. Все эпизоды видны в истории.

### 5.5 Project

Жилой комплекс застройщика (раздел 4.4).

### 5.6 Source и Agency

Source — откуда берём данные (портал, сайт агентства, фид, площадка аукционов). Agency — бизнес, который продаёт. У одного Agency может быть несколько Source.

`source_kind`: `portal`, `agency_site`, `developer_site`, `auction_platform`, `servicer`, `feed`.

`acquisition_method` (в Listing): `site`, `feed`, `manual_upload`, `search_engine`.

## 6. Источники и сбор

### 6.0 Multi-source Data Acquisition Layer (решение 27.09.2026)

**Принцип: идём вверх по цепочке** — туда, откуда объявления получают сами порталы:

```
владелец / агентство / застройщик / банк → CRM → XML / API → порталы (Spitogatos, XE, Indomio, Plot…)
                                            └──────────────→ Spiti Radar (ещё один destination)
```

Защиты порталов (Imperva, Cloudflare, DataDome) перестают быть центральной проблемой: ядро базы не зависит от порталов. Если любой портал закроет доступ роботам, продукт продолжает работать.

**Архитектура:**

```
                                  SPITI RADAR
        ┌──────────────────────────────┼───────────────────────────────┐
   SUPPLY FEEDS                    DISCOVERY                       PUBLIC / REO
   CRM XML/API (Feed Hub)          ΓΕΜΗ Agency Registry            AADE e-auctions
   сайты агентств (crawler)        поисковики (Google/Bing API)    ΕΤΑΔ / HPPC
   застройщики                     email-уведомления порталов      doValue / Altamira
   частные владельцы               портал-партнёрства              Intrum, банки (Alpha PropertyNow…)
   открытые порталы (XE.gr)        Source Recovery Engine
        └──────────────────────────────┼───────────────────────────────┘
                                   INGESTION
                                   NORMALIZER
                                  DEDUP ENGINE (раздел 7)
                                 PROPERTY ENTITY
                 текущая цена · история цены · статус · first seen · все источники · агентство
```

**Property ≠ объявление.** Один объект имеет несколько Listing из разных источников (сайт агентства ID 55431, Spitogatos ID 112345, XE ID 98234, Indomio ID 322211); пользователь видит один объект с пометкой «найден на N сайтах» и историей цены. Портал никогда не владеет карточкой: владелец карточки — первичный источник.

**Каналы по приоритету:**

| # | Канал | Способ | Что даёт |
|---|---|---|---|
| 1 | **CRM и фиды агентств — Feed Hub** | Spiti Radar подключается как ещё один портал-получатель в Channel Manager CRM (Estate+, e-agents/ilistCRM, Real Status и др.): агентство включает «Публиковать в Spiti Radar», мы регулярно забираем фид (XML / JSON / CSV / REST / webhook). Адаптеры под распространённые схемы фидов | основная часть агентского предложения, точные данные, статусы, обновления |
| 2 | **Сайты агентств и застройщиков — crawler** | sitemap → новые/изменённые объекты, правила ниже | агентства без CRM-интеграции, новостройки |
| 3 | **ΓΕΜΗ Agency Registry** | официальный ΓΕΜΗ Open Data REST API: все активные компании с real-estate ΚΑΔ (по классификатору ΚΑΔ 2025, вся группа brokerage/real-estate, не один код) по региону → сайт → проверка сайта → CRM/CMS → feed / sitemap / API → crawler или предложение интеграции | полный и постоянно обновляемый реестр агентств (заменяет ручной поиск) |
| 4 | **Институциональные, REO и аукционы** | коннекторы к порталам сервисеров и банков (doValue/Altamira, Intrum REO, Alpha Bank PropertyNow и др.), AADE e-auctions, ΕΤΑΔ/HPPC | REO, аукционы, государственная недвижимость (сегменты раздела 4) |
| 5 | **Открытые порталы** | XE.gr — разрешённые robots.txt страницы выдачи | частные владельцы (FSBO) |
| 6 | **Портал-партнёрства** | официальный запрос B2B read-access / data feed / syndication: XE (Ad Viewing API — приватный, по запросу), Indomio (API/XML по соглашению), Spitogatos (профессиональная интеграция) | полные данные порталов законно |
| 7 | **Email-уведомления** | сохранённые поиски на порталах (Spitogatos, Indomio и др.) → выделенный ящик → разбор писем → новые URL в очередь (push, без обхода) | детектор новых объявлений |
| 8 | **Discovery через поисковики** | лицензированный search API: новый URL портала → ID, район, фрагмент заголовка | обнаружение, не источник карточки |
| 9 | **Source Recovery Engine** | для объекта, найденного только на портале: поиск по уникальному сочетанию (м² + район + цена + фрагмент заголовка) → находим тот же объект на сайте агентства → карточка строится из первичного источника | перевод «портальных» объектов на первоисточник |
| 10 | **Browser collector** (расширение) | ручное сохранение по действию пользователя; последний резерв, когда объект обнаружен, а другого источника нет | закрытие единичных пробелов |

**Не строим ядро на:** обходе защиты порталов (подмена отпечатка браузера, CAPTCHA-solving, ротация прокси) и на сторонних scraper-сервисах порталов (Apify-actors и т.п.): блокировки и юридический риск (условия площадок — например, Plot.gr прямо запрещает автоматический сбор без письменного разрешения; право ЕС о базах данных — извлечение существенной части и систематическое извлечение малых частей) лишь переносятся на подрядчика. Допустимо только как временный gap-filler после отдельной проверки прав.

**Экономный обход сайтов (канал 2):**

- sitemap.xml (дата `lastmod`) → страницы новых объектов → ID объявления;
- условные запросы `If-Modified-Since` / `If-None-Match` (Last-Modified, ETag);
- заново скачивать только новые и изменённые объявления; остальные — Observation «ещё на месте» без повторного разбора;
- при лимите страниц на сайт — сначала самые свежие;
- вежливость — раздел 2, п. 4.

**Конкуренты и аналоги, изучить:** Prosperty (агрегатор: частные владельцы + REO + аукционы).

**Ближайшие действия (владелец продукта + разработка):**

1. Письма CRM-провайдерам (Estate+, e-agents/ilistCRM, Real Status/iarts): подключение Spiti Radar как destination-портала в Channel Manager; формат фида.
2. Письмо XE: коммерческий доступ к Ad Viewing API / listing data feed для consumer metasearch с переходом на оригинал. Аналогичные запросы — Indomio, Spitogatos.
3. Регистрация в ΓΕΜΗ Open Data API (ключ доступа) → автоматический Agency Registry.
4. Feed Hub: приём XML/JSON/CSV/REST, адаптеры популярных схем.
5. Коннекторы REO/аукционов (список в `data/sources/auctions_servicers.csv`).
6. Выделенный ящик и сохранённые поиски для email-уведомлений.

### 6.4 Доступность порталов и сбор через поисковые системы

Проверка 27.09.2026 (запрос с сервера, заголовки обычного браузера):

| Портал | Прямой доступ | Защита | Через поиск (`site:`) |
|---|---|---|---|
| XE.gr | да | — | да |
| Spitogatos | нет | Imperva («Pardon Our Interruption») | да |
| Spiti24 | нет | Imperva (та же сеть, что Spitogatos) | да |
| Tospitimou | нет | Imperva (та же сеть, что Spitogatos) | да |
| Indomio | нет (403) | DataDome (CAPTCHA) | да |
| Plot.gr | нет (403) | Cloudflare challenge | да |
| xo.gr | нет (403) | Cloudflare challenge | да |
| vrisko.gr, RE/MAX, Century 21, KW Greece, Golden Home, Green-Acres, Greek Property Finder | да | — | не требуется |

Итог: из пяти порталов первой очереди напрямую доступен только XE.gr. Защиту не обходим (раздел 2, п. 3).

Для закрытых порталов используется **сбор через поисковые системы**: мы не заходим на сайт портала, а берём то, что поисковик уже проиндексировал и показывает в выдаче.

Что даёт поиск (проверено на Калама́рии):

- URL и ID объявления: `spitogatos.gr/aggelia/{id}`, `spiti24.gr/{id}`, `indomio.gr/aggelies/{id}/`, `plot.gr/{id}-...`;
- заголовок: тип, площадь, район, у части порталов цена (Spiti24, Plot.gr, Indomio);
- сниппет: этаж, комнаты, год постройки, иногда цена;
- страницы категорий с числом объявлений по району (например, Plot.gr: ~2 311 квартир на продажу в Калама́рии; Spitogatos: ~2 214);
- страницы каталогов агентств (xo.gr — список агентств по районам).

Ограничения:

- данные неполные и могут устареть на дни–недели (зависит от переиндексации поисковиком);
- нет фото, полного описания, точных координат;
- поисковик показывает не все объявления, покрытие неизвестно — **нельзя** использовать для статистики рынка и для перевода объявлений в REMOVED;
- Google и другие поисковики запрещают автоматический парсинг своей выдачи — использовать только **официальный API поисковой системы** (платный, с лимитами запросов); выбор API и его условий — открытый вопрос (раздел 16).

Как используем в продукте:

1. **Discovery**: находить новые объявления, ID и агентства на закрытых порталах.
2. **Сверка**: есть ли объект с сайта агентства также на Spitogatos/Indomio/Plot.gr (для метрики «эксклюзивное покрытие» и дедупликации).
3. **Выдача**: объявление из поиска показывается только со ссылкой на оригинал и с пометкой «данные из поисковой системы, проверьте на сайте источника». В Listing хранить `acquisition_method=search_engine` и понижать confidence полей.

Долгосрочно для закрытых порталов — партнёрство или официальный фид (п. 1 раздела 6.3). Основной источник объектов — сайты агентств (раздел 6.5).

### 6.5 Сайты агентств — основной источник

Главная идея продукта: **собрать в одном месте объекты с сайтов агентств, прежде всего маленьких**. На порталы агентство выставляет лишь малую часть своих объектов (размещение платное), основная база — на его собственном сайте. Spiti Radar ищет по сайтам агентств и отправляет покупателя обратно на сайт агентства.

Согласие агентства **не требуется**: сайт агентства публичный, мы индексируем его по правилам раздела 2 (ссылка на оригинал, правило robots.txt из п. 4, без обхода защиты), агентство может исключить себя через opt-out (раздел 13).

Приоритет: **независимые маленькие агентства** выше франшиз (RE/MAX, Century 21, Golden Home, KW) — у франшиз объекты и так на порталах.

Реестр агентств Салоник: `data/sources/agencies_thessaloniki.csv`. Источники:

### 6.6 Discovery

Discovery только **регистрирует** новые источники в статусе `NEEDS_REVIEW`. Сбор данных начинается после ручного одобрения.

Откуда берутся агентства (по приоритету):

1. **Каталоги агентств на порталах** — у Spitogatos, Spiti24, Indomio есть страницы «агентства по району» (шаблоны URL в `data/sources/portals.csv`). По данным каталога Spitogatos: ~477 агентств в муниципалитете Салоник и ~318 в пригородах.
2. **Объявления на порталах** — название и контакты агентства в карточке объявления.
3. **Греческие «жёлтые страницы»** (vrisko.gr, xo.gr) — находят агентства, которых **нет на порталах**. Это главный канал к объектам, не выставленным на агрегаторах.
4. **Франшизы** (RE/MAX, Century 21, Keller Williams, Golden Home) — один парсер покрывает все офисы сети.
5. Сайты сервисеров и площадки аукционов.

Для каждого найденного агентства: название, адрес офиса, район, телефон офиса, сайт, на каких порталах присутствует, есть ли на сайте раздел объектов, платформа сайта. Агентство без сайта с объектами — `status=NO_OWN_LISTINGS`, остаётся в реестре для атрибуции.

Ключевая метрика реестра: **доля агентств с собственными объектами, не найденными на порталах** («эксклюзивное покрытие»).

### 6.7 Health monitoring

Если количество объявлений источника упало больше чем на 50% за скан — скан помечается `SUSPECT`, объявления **не** переводятся в REMOVED, приходит алерт админу.

## 7. Дедупликация

### 7.1 Поиск кандидатов

Кандидаты для нового Listing: тот же сегмент (или `unknown`), в радиусе 3 км, площадь ±15%, тип объекта совпадает.

### 7.2 Сигналы и вес

| Сигнал | Сила |
|---|---|
| ≥ 3 совпавших фото (pHash) | очень сильный |
| точные координаты ≤ 30 м + этаж + площадь ±5% | сильный |
| хэш текста описания (minhash ≥ 0.8) | сильный |
| этаж + площадь ±5% + комнаты + район | средний |
| агентство + цена ±3% | слабый |

Результат — `property_match_confidence`:

- ≥ 0.90 — автоматически объединяем;
- 0.60–0.90 — очередь Duplicate Review;
- < 0.60 — новый Property.

Внутри Project (новостройки) — правило 4.4.3.

### 7.3 Защита от ошибочных объединений

- Разный этаж при известных этажах у обоих → не объединять автоматически.
- Кластер не может разрастаться транзитивно: новый Listing сравнивается со всеми Listings Property, а не с одним.
- Все объединения и разделения пишутся в `property_merges`, могут быть отменены.

### 7.4 Эталонная выборка

До запуска matcher — вручную разметить 300 пар Listing (дубль / не дубль) по Салоникам, включая: новостройки, объявления в разных районах, аукционы. Метрики matcher считаются на этой выборке.

## 8. Аналитика

### 8.1 Правила

- Только **медиана** и перцентили, не среднее.
- Аналоги: тот же сегмент, тот же район (или радиус), тип объекта, площадь ±30%, при наличии — сопоставимый год/состояние.
- Исключаются: аукционы, сервисеры (для рыночной вторички), доли, голая собственность, `price_outlier`, `price_type=from`, дубли (считается одна цена на Property — минимальная актуальная).
- Минимальная выборка — 8 аналогов. Меньше → «недостаточно данных», процент отклонения не показывается.
- Всегда показывать размер выборки и её состав: «На 11% ниже медианы 34 сопоставимых объявлений вторички в Kalamaria (45–75 м²)».

### 8.2 Цены предложения и сделок

Показываются раздельно. В MVP — только цены предложения. Открытых данных о ценах сделок по объектам в Греции, насколько известно, нет; возможны агрегированные индексы (Банк Греции) — только как фон.

### 8.3 Все расчёты — оценка

Инвестиционные показатели, доходность, стоимость ремонта помечаются «оценка».

## 9. Поиск

- Запрос: интерфейс или свободный текст на EN/RU/EL.
- Свободный текст разбирается в структурированные параметры; **разобранный запрос всегда показывается пользователю** с возможностью исправить.
- Жёсткие условия («до 130k», «не цоколь») фильтруют. Мягкие («желательно лифт») влияют только на Match Score.
- Любое изменение параметра создаёт новый запрос. Старые параметры не переиспользуются.
- Результат — Properties, не Listings.
- В каждой выдаче: сколько источников опрошено / ответило / упало. Сообщение «рынок пуст» только если все релевантные источники ответили успешно.

## 11. Метрики качества и Definition of Done

### 11.1 Метрики

| Метрика | Цель для Фазы A |
|---|---|
| Открывающиеся ссылки среди показанных | ≥ 98% |
| Точность дедупликации (без ложных объединений) | ≥ 98% на эталонной выборке |
| Полнота дедупликации | ≥ 85% |
| Точность сегмента `auction` | ≥ 95% |
| Свежесть: порталы / агентства | проверка ≤ 24 ч / ≤ 72 ч |
| Доля ACTIVE-источников | ≥ 90% |
| Ответ бота на поиск (p95) | ≤ 5 с |
| Ложные PRICE_DROP уведомления | < 1% |

### 11.2 Definition of Done Фазы A

Запрос «Thessaloniki → Kalamaria, €80–150k, 50–80 м², 1 этаж+»:

1. параметры реально применены (проверяется тестом на каждый фильтр);
2. в выдаче объекты минимум из 2 порталов и 10 агентств;
3. аукционы не попадают в обычную выдачу и медианы;
4. дубли, включая опубликованные в разных районах, объединены;
5. у объекта видно количество источников и цены у каждого;
6. все ссылки ведут на конкретное объявление и открываются;
7. сохраняется first_seen, при следующем скане фиксируется изменение цены;
8. пользователь получает уведомление о новом подходящем объекте;
9. интерфейс работает на EN, RU, EL;
10. метрики раздела 11.1 выполняются 14 дней подряд.

## 12. Технические требования

- Python, PostgreSQL + PostGIS.
- Планировщик задач (очередь + cron).
- HTTP-сбор; браузерный рендеринг только при необходимости.
- Перцептивные хэши фото (pHash) — вычисляются в памяти, фото не сохраняется.
- LLM — для разбора запросов и извлечения признаков из греческого текста; ответы кэшируются, бюджет LLM ограничен в конфигурации.
- Один VPS на старте, ежедневные бэкапы базы.
- Все пороги (радиусы, допуски, confidence, пороги аукционов) — в конфигурации, не в коде.

---

## 13. Opt-out и атрибуция

- Форма «Remove / Opt out / Update source» + правило robots.txt из раздела 2, п. 4.
- Исключение источника выполняется в течение 72 часов, запросы логируются.
- В каждой карточке: «Source: …» и ссылка на оригинал. Нельзя создавать впечатление, что объявление принадлежит платформе или агентству Jeny Shir.
- Услуги Jeny Shir — отдельный, явно обозначенный блок, не влияющий на ranking.
